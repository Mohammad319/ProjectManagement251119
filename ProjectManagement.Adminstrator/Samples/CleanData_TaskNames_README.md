# Clean Data task-name template

This file is for the `Clean Data` page in ProjectManagement.Adminstrator.

Recommended unified column order:

1. `RowType` - `T` for task rows, `R` for resource rows. Use only `T` rows when the file has task names only.
2. `Code` - task code on task rows.
3. `ParentCode` - parent task code on resource rows.
4. `Name` - task name when `RowType=T`, resource name when `RowType=R`.
5. `Unit` - task unit on task rows, resource unit on resource rows.
6. `TaskNameSynonym1` - optional alternate wording for the task name.
7. `TaskNameSynonym2` - optional second alternate wording for the task name.
8. `TaskUnitSynonym1` - optional alternate wording for the task unit.
9. `TaskUnitSynonym2` - optional second alternate wording for the task unit.
10. `ResourceType` - for resource rows, for example `Material`, `Machine`, `Worker`, `Subcontractor`.
11. `UnitCost` - optional unit cost for resource rows.

`Quantity` is optional and intentionally not part of the basic template because project quantities usually come from the user later. If a file includes `Quantity`, the importer still accepts it.

The order is recommended, not mandatory, when the headers are clear. The importer recognizes common header names such as `Code`, `Name`, `Quantity`, `Unit`, `TaskNameSynonym1/2`, and `TaskUnitSynonym1/2`. `Title` is also accepted as an alias for `Name`.

The same template works for task-only files and task-resource files. If there are no `R` rows, the importer treats the file as clean task data only.

For JSON, use an array of tasks. Each task has a `resources` array. JSON is the safest format when the file is generated by another system or an AI tool because each resource stays nested under its task.
Use `taskNameSynonyms` and `taskUnitSynonyms` arrays in JSON, or the single fields `taskNameSynonym1`, `taskNameSynonym2`, `taskUnitSynonym1`, and `taskUnitSynonym2`.
